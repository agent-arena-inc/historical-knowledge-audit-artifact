# Historical Knowledge Contamination Audit Artifact

This repository package supports a two-case study of historical knowledge
contamination in LLM-agent simulations. It is organized around three distinct
reproducibility levels:

1. **Recompute reported analyses** from supplied transcripts, cached labels,
   annotations, and deterministic scripts.
2. **Rerun audit instruments** from documented prompts and model settings.
3. **Regenerate simulations under information controls**, where an executable
   runner or a documented access arrangement is required.

The current package is a development scaffold. Cached-judgment denominators are
reconciled in a reproducible table, but substantive labels remain provisional
until the selected outputs are independently human-coded.

## Quick start

Python 3.10 or newer is sufficient for the deterministic artifact scripts. No
third-party packages or API credentials are needed to build the manifest,
summarize cached judgments, or verify file hashes.

```bash
git clone REPOSITORY_URL
cd historical-knowledge-audit-artifact
make all
```

`make all` rebuilds the manifest, audit-instrument snapshot, provisional
evidence table, and harmonized organizational decision-output table from
`data/cases`, then verifies file hashes and anonymity. The
scripts never modify source transcripts or cached model outputs. No network,
third-party package, API credential, or proprietary simulation engine is needed
for this recomputation level.

## Interpretation limits

- A keyword hit is candidate evidence, not a confirmed information violation.
- Agreement among model judges is not an external correctness benchmark.
- A seeded input is not automatically a positive output label.
- Stability under a de-identification control supports robustness only under
  that bundled transformation; it does not isolate an identity effect.
- Passing the audit does not establish absence of latent historical knowledge,
  reproduction of human reasoning, or validity as a model of human behavior.

## Independent coding packets

The internal working copy contains separate evaluator-blinded coder packets and
a private sample key. These active-study files are intentionally omitted from
the reviewer release. They should not be shared with coders alongside the
provisional evidence table or automated evaluator outputs. Adjudicated,
de-identified annotations will be added to the reviewer release after coding is
frozen.

The internal packets hide original run IDs, sampling strata, and automated
labels. They retain exact scenario inputs because supplied information and
prescribed agent objectives are part of the validity judgment.
